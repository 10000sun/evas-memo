# 사용자 자동 등록 · 비공개 공유 · 사용자 태그 설계

기존 설계들에 더한다. 충돌하면 이 문서가 우선한다.

## 1. 사용자 자동 등록 (메모·캘린더 둘 다)
- **목표**: 디스코드로 한 번이라도 접속한 사람은 자동으로 "사용자 목록"(`members`)에 등록된다. 관리자 설정 화면(`admin.html`) 맨 아래 "사용자" 구역에 모든 등록 사용자가 보인다(이름, 디스코드 ID, 마지막 접속, 현재 권한). 관리자는 거기서 권한(관리자/편집자)을 지정하거나 기본값으로 되돌린다(기존 기능 유지).
- **권한 의미는 바뀌지 않는다(중요)**: `members`는 "누가 접속했는지" 기록일 뿐이고 권한은 기존 `users` 표(`admin`/`editor`)와 `EVAS_OPEN_EDIT` 규칙 그대로다. 자동 등록이 편집 권한을 주면 안 된다(`EVAS_OPEN_EDIT=0`일 때 접속자 전원이 편집자가 되는 사고 금지).
- **표**: `members(id TEXT PRIMARY KEY, name TEXT NOT NULL, first_seen TEXT NOT NULL, last_seen TEXT NOT NULL)`. 로그인 콜백과 `/auth/dev`(개발용)와 `GET /api/me`(이미 로그인해 둔 세션이 다음 요청에서 등록되도록)에서 upsert(이름은 최신으로 갱신, `last_seen`은 하루에 한 번 정도만 갱신해 쓰기를 줄인다). 개발용 헤더 인증도 같은 경로를 탄다.
- **API**: `GET /api/members`(관리자만) → `[{id, name, first_seen, last_seen, role}]`(role은 현재 유효 권한 admin/editor/viewer). 메모 앱에서는 비공개 공유의 사람 고르기용으로 `GET /api/members/pick`(로그인한 누구나, `[{id, name}]`만, 이름 검색 `q` 지원)을 따로 둔다(ID·접속 시각은 관리자만).
- **관리자 화면**: 기존 "관리자" 구역(사용자 추가 폼) 아래에 "접속한 사용자" 목록. 목록에서 바로 권한 변경·기본값으로 되돌리기. 기존 사용자 추가 폼은 유지(아직 접속 안 한 사람 미리 등록용).
- **기존 데이터**: 이미 `users`에 있는 사람은 첫 접속 때 `members`에 들어간다(마이그레이션 없음). `EVAS_ADMIN_IDS`로 시드된 관리자도 접속 전에는 목록에 없을 수 있다 → 목록은 `members` ∪ `users`를 합쳐 보여 준다(접속 기록이 없으면 "접속 기록 없음").

## 2. 비공개 공유 (메모 앱만) — 공동 메모·폴더에 "공개 범위"
- **목표**: 공동 메모와 공동 폴더는 만든 사람이 **공개 범위를 "전체"(기본) 또는 "선택한 사람"**으로 정할 수 있다. 선택한 사람은 `members`(한 번이라도 접속한 사람) 중에서 이름 검색으로 고른다. **관리자는 항상 전부 보인다**(비공개 메모·폴더의 존재, 내용, 사람 목록까지). 만든 사람은 언제나 본인 것을 본다.
- **보이는 사람의 권한(기본값, 사용자 확인 필요)**: 선택된 사람은 **보기와 편집 둘 다** 가능(공동 메모와 같은 실시간 공동 편집). 사람별 "보기만"은 하지 않는다.
- **폴더**: 폴더가 비공개이면 그 안의 모든 메모는 **그 폴더의 사람 목록**을 따른다(메모 쪽 설정은 무시·비활성). 비공개 폴더 안의 폴더(하위)도 같은 목록을 이어받는다. 폴더 목록을 바꾸면 안의 메모에 즉시 적용된다. 메모를 비공개 폴더로 옮기면 그 폴더의 목록을 따르고, 공개 폴더로 옮기면 메모 자신의 설정으로 돌아간다.
- **변경 권한**: 공개 범위·사람 목록은 **만든 사람과 관리자**만 바꾼다. 선택된 사람은 목록을 보되 바꾸지 못한다.
- **존재 숨김**: 목록에 없는 사람에게 비공개 메모·폴더는 존재하지 않는 것과 같은 404/목록 제외(검색, 직접 주소, WebSocket, 폴더 목록, 활동 기록, 푸시, `rev`, 캘린더 내부 API, 태그 힌트 모두). 사람을 목록에서 빼면 그 사람의 열려 있는 편집 연결은 즉시 닫힌다(코드 4404).
- **활동 기록·푸시**: 비공개 공유 메모·폴더는 기록·푸시를 만들지 않는다(전체 공개 메모와 달리 제목이 모두에게 나가면 안 된다). 비공개로 바꾸는 순간, 그 메모의 기존 활동 항목은 제목이 남아 있어도 이미 공개된 것으로 본다(전율과 동일).
- **캘린더 연동**: 비공개 공유 메모는 `/internal/link/*`에 나가지 않는다(전체 공개 메모만). 메모 안의 `@` 힌트에는 본인이 볼 수 있는 것만 나온다.
- **전환**: 전체 ↔ 선택한 사람 언제든 전환 가능(선택한 사람 → 전체로 바꾸면 모두에게 보이므로 확인창). 공동 → 전율/개인 이동 시 사람 목록은 버린다. 개인/전율 메모는 이 기능과 무관.
- **화면**: 편집 화면과 폴더 줄에 자물쇠 표시와 "공개 범위" 버튼 → 사람 고르기 창(이름 검색, 체크, 선택된 사람 칩, 저장). 카드에 자물쇠+"N명" 표시. 사람 목록은 만든 사람·관리자·선택된 사람만 볼 수 있다.

## 3. 사용자 태그 (@)
- 메모 본문에서 `@` 힌트에 **사람**도 나온다(일정·메모와 구분 표시, 이름 검색, `members/pick` 사용). 고르면 `[@이름](user:<디스코드 ID>)` 형식의 마크다운 링크가 들어가고(미리보기·에디터에서는 클릭할 수 없는 "사람 칩"으로 표시, 로그에 `javascript:` 같은 위험 스킴이 생기지 않게 `user:`는 앱이 직접 렌더), 연결 칩 줄에도 사람 칩으로 모인다. 이름이 나중에 바뀌어도 칩은 최신 이름을 `members`에서 조회해 보여 준다.
- **태그가 접근 권한을 주지는 않는다**: 비공개 메모에서 사람을 태그해도 그 사람이 보게 되지 않는다(공개 범위는 따로 정한다). 태그는 알림(푸시)을 보내지 않는다(범위 밖; 필요하면 다음 작업).
- 캘린더 쪽에는 사람 태그를 넣지 않는다(이번 범위 밖).

## 비목표
사람별 보기 전용 권한, 그룹/팀 단위 공유, 태그 알림·푸시, 접근 요청, 개인·전율 메모의 공유, 사용자 탈퇴·삭제 UI(기존 사용자 삭제는 유지), 캘린더의 비공개 일정.

## 실패로 치는 것
- `members` 자동 등록 때문에 누군가 의도치 않게 편집/관리자 권한을 얻는 것.
- 비공개 공유 메모·폴더의 제목·존재가 목록에 없는 사람(관리자 제외)에게 드러나는 모든 경로(REST, 검색, WS, 폴더, 활동/rev/푸시, 캘린더 내부 API, 태그 힌트, 오류 문구 차이).
- 목록에서 뺀 사람이 열려 있던 연결로 계속 읽거나 편집하는 것. 폴더 목록 변경이 안의 메모에 반영되지 않아 일부가 옛 목록으로 남는 것.
- 관리자가 비공개 메모를 못 보는 것.
- 운영 DB 이전 실패/데이터 유실(`members`·공유 표 추가, `memos`/`folders`에 열 추가는 `ALTER`로 안전하게).
