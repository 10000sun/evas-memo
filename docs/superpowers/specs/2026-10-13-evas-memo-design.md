# evas-memo 설계

## 목적
evas-calendar와 같은 팀(디스코드 서버)이 쓰는 **공동작업 메모 웹앱**. 한 메모를 여러 명이 동시에 구글 문서처럼 같이 치고, 개인 메모는 본인만 본다. 로그인·권한·화면 구성·운영 방식은 evas-calendar를 그대로 따른다(`E:\폴더\개발\evas-calendar` 참고).

## 목표
- **메모 두 종류**: 개인 메모(본인만 열람·편집) / 공동 메모(로그인한 누구나 열람·편집).
- **개인 → 공동 이동, 공동 → 개인 복사**: 편집 화면의 "공동으로 옮기기 / 개인으로 복사" 버튼. (이동 시) 내용·분류·작성자는 그대로 유지하고 종류만 바뀐다(Yjs 문서를 새로 만들지 않음). 개인 → 공동은 이동이다(개인 쪽에는 남지 않는다).
  - 개인 → 공동: 소유자가 한다. 확인창("모든 사람에게 보입니다") 후 이동. 공동 활동 기록에 '작성'으로 남고 푸시도 새 공동 메모와 같이 간다.
  - 공동 → 개인: **복사**다. 공동 메모는 그대로 남고, 누른 사람에게 본문·제목·분류가 같은 개인 메모가 새로 생긴다(작성자·소유자는 누른 사람, 이후 두 메모는 서로 무관). 열람 가능한 사람 누구나 할 수 있고 활동 기록·푸시·열린 연결에는 영향이 없다.
- **내보내기(휴대폰 메모앱으로)**: 편집 화면의 "내보내기" 버튼. 휴대폰의 공유 시트(Web Share API)를 열어 아이폰 메모·안드로이드 기본 메모앱(·기타 앱)으로 제목+본문을 텍스트로 보낸다. 공유 시트가 없는 브라우저(PC 등)는 클립보드 복사로 대신하고, 복사도 막히면 `.txt` 파일 다운로드로 대신한다. 서버는 관여하지 않는 화면 기능이며 HTTPS(또는 localhost)에서만 동작한다. 개인·공동 모두 열람할 수 있으면 쓸 수 있다.
- **분류(카테고리)**: 이름 + 색. 개인·공동 메모가 같은 목록을 쓴다. 추가·수정·삭제는 **관리자만**. 메모에 분류 지정은 메모를 편집할 수 있는 사람 누구나.
- **실시간 공동 타이핑**: 같은 메모를 동시에 쳐도 서로 덮어쓰지 않고 합쳐진다. 상대의 커서와 이름이 보인다. 개인 메모도 같은 엔진이라 내 폰·PC에서 실시간으로 맞는다.
- **다크/라이트 모드** 전환(기본값은 기기 설정, 선택은 브라우저에 기억).
- **원칙: 기능은 evas-calendar를 그대로 따라가고, 다루는 내용만 일정 → 메모로 바꾼다.** 캘린더에 있는 것은 아래처럼 1:1로 옮긴다.

| evas-calendar | evas-memo |
|---|---|
| 월간 달력 + 범주 범례 | 메모 목록 + 분류 범례(칩 필터) |
| `+ 일정`, 일정 작성·수정·삭제 | `+ 메모`, 메모 작성·수정·삭제 |
| 선택 날짜 일정 목록 | 열어 본 메모 편집 화면 |
| 범주(이름·색, 관리자만 관리) | 분류(이름·색, 관리자만 관리) |
| 디스코드 로그인, `DISCORD_GUILD_ID` 서버 구성원 제한 | 동일 |
| 사용자·권한 관리(관리자/편집자), `EVAS_ADMIN_IDS`, `EVAS_OPEN_EDIT` | 동일(관리 화면에서 관리자/편집자 지정, 기본 `EVAS_OPEN_EDIT=1`) |
| 작성자·수정자 닉네임 표시 | 동일 |
| 활동 기록 + 종 아이콘 + 안 읽은 표시 | 동일(공동 메모 대상) |
| 푸시 알림(VAPID) | 동일 |
| PWA, 도움말, 새로고침, 오늘 버튼, 20초 자동 반영, 다크/라이트 | 동일(오늘 버튼은 달력 전용이라 제외) |
| 관리자 화면(`admin.html`) | 동일: 분류 관리 + 사용자 관리 |
| 배포 문서·스크립트(Caddy, DuckDNS, 작업 스케줄러, 재시작) | 동일하게 복사·이름만 수정 |
| `CLAUDE.md` 브랜치 규칙, pytest | 동일 |

달력 고유 기능은 메모에 의미가 없어 옮기지 않는다: 공휴일, `.ics` 일정 가져오기, 달력 보기, 오늘 버튼. (제 판단 — 메모용 가져오기(.txt/.md)가 필요하면 말씀해 주세요.)
- 새로 더하는 것은 메모 특성 두 가지뿐: **개인/공동 구분**과 **실시간 공동 타이핑**.

## 비목표
리치 텍스트·이미지·첨부, 오프라인 편집, 버전 기록·되돌리기, 댓글, 메모별 권한, 서버 여러 대 구성.

## 실패로 치는 것 (동작해도)
- 동시에 친 글자가 사라지거나 뒤섞이는 것.
- 개인 메모가 본인 외에게 (관리자 포함) 보이는 것. 목록·검색·활동 기록·푸시·WebSocket 어디로도 새면 안 된다.
- 관리자가 아닌 사람이 분류를 바꾸는 것.
- 서버를 재시작하면 메모가 사라지는 것.

## 만드는 방식 (제 결정 — 바꾸고 싶으면 말씀해 주세요)
- **스택**: evas-calendar와 동일. Python FastAPI + SQLite + 프레임워크 없는 JS(PWA). Windows 서버에서 uvicorn **1프로세스**로 실행(문서를 메모리에 들고 있으므로 다중 워커 금지). 배포는 Caddy + DuckDNS 방식 그대로(`docs/DEPLOY.md` 복사·수정). **배포 작업 자체는 지시 전까지 하지 않는다.**
- **동시 편집 엔진**: Yjs(CRDT). 서버는 `pycrdt`/`pycrdt-websocket`으로 WebSocket을 중계하고 문서를 SQLite에 저장한다. 브라우저 에디터는 CodeMirror 6 + `y-codemirror.next`(상대 커서·이름 표시 내장). 번들은 개발 PC에서 esbuild로 한 번 만들어 `static/vendor/`에 **커밋**한다(캘린더가 fullcalendar를 벤더링한 것과 같은 방식, 서버에 Node 불필요). 글은 일반 텍스트, 줄바꿈 자동.
  - 위험: pycrdt-websocket과 FastAPI 조합이 첫 난관. **구현 첫 단계에서 두 브라우저 동시 타이핑을 먼저 확인**하고 안 되면 방식을 다시 상의한다.
- **저장**: `memos`(id, kind=`personal|shared`, owner_id, title, category_id NULL 허용, body_text(목록·검색·미리보기용 사본), ydoc BLOB(Yjs 상태), created_by/name, updated_by/name, updated_at), `categories`, `users`, `activity`, `activity_read`, `push_subs`(캘린더 스키마 재사용). 마지막 접속자가 나가거나 일정 시간마다 Yjs 상태를 압축 저장하고, 편집 중에도 수 초 간격으로 저장해 재시작 손실을 막는다.
- **권한**: WebSocket 연결 때 세션 쿠키로 확인. 개인 메모는 owner만(연결·API 모두), 공동 메모는 로그인한 사람 누구나(서버 구성원 제한은 `DISCORD_GUILD_ID`로 캘린더와 동일). 분류 변경 API는 관리자만. 공동 메모 **삭제는 작성자와 관리자만**, 개인 메모는 본인만. 편집은 누구나.
- **제목**: 본문과 달리 입력칸 하나로 두고 잠깐 멈추면 저장·전파(마지막 저장이 이김). 제목을 동시에 고칠 일은 드물다고 보고 CRDT에 넣지 않는다.
- **분류 삭제**: 그 분류의 메모는 '미분류'가 된다(메모는 지우지 않는다). 기본 분류는 처음 실행 때 시드(예: 공지·아이디어·할 일·참고 — 바꿀 수 있음).
- **화면**: 상단 `개인 | 공동` 탭 + 분류 칩 필터 + 검색 + 새 메모 버튼, 목록은 최근 수정순 카드(제목·분류 색·미리보기·수정자·시각). 카드를 열면 편집 화면(제목, 분류 선택, 본문, 지금 같이 보는 사람 표시, 저장 상태). 휴대폰 우선 반응형. 헤더에 다크/라이트·새로고침·활동 종·도움말·(관리자) 관리.
- **활동 기록·푸시**: 공동 메모의 작성·삭제, 그리고 편집은 같은 사람의 연속 편집을 묶어 한 건으로 남긴다(타이핑마다 남기지 않음). 개인 메모는 기록·푸시 대상이 아니다. 푸시는 공동 메모 새로 작성·삭제만 보낸다(편집 푸시는 소음이라 제외 — 제 결정).
- **크기 제한**: 본문 100,000자(제 결정). 넘으면 입력 거절 안내.
- **자동 반영**: 목록은 캘린더처럼 20초마다 갱신, 열려 있는 메모는 WebSocket으로 즉시.

## 작업 순서와 브랜치
레포 `10000sun/evas-memo`. 작업마다 `feat/*` 브랜치 → 모두 `develop`에 모은 뒤 `develop`에서 구동 테스트. **`main`에는 "배포하라"는 지시가 있을 때만 올린다.** 지금 레포가 비어 있어 `develop`을 먼저 푸시하면 GitHub 기본 브랜치가 `develop`이 되는데, 배포 때 `main`을 만들고 기본 브랜치를 `main`으로 바꾼다.
1. 실시간 편집 뼈대(두 브라우저 동시 타이핑 검증) 2. 로그인·권한·DB 3. 메모·분류 API와 관리자 화면 4. 목록·편집 UI, 다크/라이트 5. 활동 기록·푸시·PWA·도움말 6. 문서(README, DEPLOY, CLAUDE.md).

## 테스트
pytest: 이동·복사(개인→공동 이동 후 타인 열람 가능·본인 개인 목록에서 사라짐·본문 보존, 공동→개인 복사 후 원본 유지·복사본은 복사한 사람만 열람·원본 수정이 복사본에 번지지 않음, 남의 개인 메모 이동 거절), 권한(개인 메모 비노출·타인 WebSocket 거절, 분류 관리자 전용, 삭제 권한), Starlette TestClient WebSocket 두 개로 동시 입력 병합·재연결·재시작 후 복원, 활동 묶기, 100,000자 제한. 수동: 휴대폰(아이폰·안드로이드)에서 내보내기 → 메모앱에 제목·본문이 들어가는지, PC에서 클립보드 폴백, 브라우저 두 개(휴대폰 포함)로 동시 타이핑·상대 커서·다크/라이트.

## 빌더에게 남기는 것
CSS 세부, 목록 카드 디자인, 기본 분류 색, 저장 간격 수치, 오류 문구는 evas-calendar 스타일에 맞춰 알아서 정한다.
