# evas-memo 추가 설계: 폴더 · 마크다운 · 커서 색

기존 설계(`2026-10-13-evas-memo-design.md`)에 더하는 것. 충돌하면 이 문서가 우선한다.

## 목표
- **마크다운**: 본문은 마크다운 원문으로 쓰고(실시간 공동 편집 그대로), 편집 화면에서 `편집 | 미리보기`를 전환한다. 입력 중에도 마크다운 문법 강조. 지원: 제목, 굵게, 기울임, 취소선, 목록, 체크박스(미리보기에서는 읽기 전용), 인용, 인라인·블록 코드, 링크, 표, 구분선. 미리보기는 반드시 HTML 무해화(스크립트·이벤트 속성·`javascript:` 링크 제거, 링크는 새 탭 + `rel="noopener noreferrer"`). 내보내기는 원문 그대로.
- **폴더**: 개인 메모는 각자 자기 폴더, 공동 메모는 공동 폴더에 보관한다. 폴더 안에 하위 폴더는 **1단계까지만**(폴더 > 하위 폴더, 그 아래는 불가). 분류(색 태그)는 그대로 유지하고 폴더는 "위치"다.
- **커서 색**: 같이 편집하는 사람마다 닉네임 + 색이 커서에 붙는다(이미 있음). 같이 접속한 사람끼리 색이 **겹치지 않게** 한다.

## 비목표
폴더 공유 권한 세분화, 폴더 이동(상위 변경), 폴더 색·아이콘, 폴더 단위 알림·활동 기록, 체크박스를 미리보기에서 눌러 원문 수정, 마크다운 WYSIWYG 편집, 3단계 이상 중첩.

## 실패로 치는 것
- 미리보기에서 메모 내용으로 스크립트가 실행되는 것(XSS).
- 개인 폴더의 이름·존재·구조가 본인 외에게 보이는 것(API, 목록, 메모 이동·복사 어디로도).
- 폴더를 지웠는데 메모가 사라지는 것.
- 이미 운영 중인 DB(폴더 도입 전 스키마)가 새 버전에서 열리지 않거나 데이터가 사라지는 것.

## 결정 (제 판단 포함)
- **폴더 권한(사용자 선택 1번)**: 공동 폴더는 편집 권한이 있는 누구나(`admin|editor`) 만들고 이름을 바꿀 수 있고, **삭제는 만든 사람이나 관리자**만. 개인 폴더는 본인만 만들고 바꾸고 지운다. 공동 폴더 목록은 로그인한 누구나 볼 수 있다.
- **폴더 삭제**: 그 폴더와 하위 폴더를 지우고, 그 안의 메모는 지우지 않고 "폴더 없음"(`folder_id` NULL)이 된다.
- **이동·복사**: 개인 → 공동 이동 시 공동의 "폴더 없음", 공동 → 개인 복사 시 개인의 "폴더 없음"(폴더는 종류·소유자에 묶여 있어 따라가지 않는다).
- **이름 규칙**: 폴더 이름 1~30자, 같은 위치(같은 종류·소유자·상위)에서 중복 불가.
- **메모의 폴더 지정**: 메모를 편집할 수 있는 사람이 폴더를 바꿀 수 있다(제목·분류와 같은 권한). 폴더는 메모와 같은 종류(개인이면 본인 폴더, 공동이면 공동 폴더)여야 한다.
- **스키마 이전**: 운영 DB에 `folders` 표와 `memos.folder_id` 열을 `db.init`에서 안전하게 추가한다(`CREATE TABLE IF NOT EXISTS` + 열이 없으면 `ALTER TABLE`). 기존 데이터는 그대로.
- **라이브러리**: 마크다운 렌더 `marked`(GFM) + 무해화 `DOMPurify`, 입력 강조 `@codemirror/lang-markdown`. 개발 PC에서 esbuild로 번들해 `static/vendor/`에 커밋한다(서버에 Node 불필요, 기존 방식).
- **커서 색 배정**: 각 클라이언트가 선호 색(사용자 id 해시)을 먼저 쓰고, 같은 색을 쓰는 다른 접속자가 있고 그 접속자의 clientID가 더 작으면 비어 있는 색으로 바꾼다(awareness로 서로 알림). 팔레트는 접속 가능 인원보다 충분히 크게(12색 이상).
- **활동 기록·푸시**: 폴더 변경은 기록하지 않는다.
- **화면**: 목록 위에 폴더 줄(`전체 · 폴더 없음 · 폴더들 · + 새 폴더`), 폴더를 고르면 그 하위 폴더 줄이 이어서 나온다. 선택한 폴더에서 이름 바꾸기·삭제. 메모 카드에 폴더 경로 표시. 편집 화면에 폴더 선택. 모바일 우선.
