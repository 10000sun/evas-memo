# 메모 ↔ 캘린더 연동 설계

evas-memo(`E:\폴더\개발\evas-memo`)와 evas-calendar(`E:\폴더\개발\evas-calendar`)는 서로 다른 서버·DB·도메인이다. 둘을 `@` 태그와 앱 전환 링크로 잇는다. 이 문서의 "계약" 절이 두 레포 구현의 공통 기준이다.

## 목표
- **메모 본문에서 `@`**: 입력하면 캘린더 일정과 메모(다른 메모)가 힌트 목록으로 뜬다. 고르면 `[@제목](주소)` 마크다운 링크가 본문에 들어간다. 편집 화면 위에 태그한 일정·메모가 **연결 칩 줄**로 모이고, 칩을 누르면 해당 캘린더 일정/메모로 바로 이동(같은 탭)한다. 본문의 링크도 기존 방식(미리보기 클릭, 편집 중 ↗)으로 열린다.
- **캘린더 일정의 메모 칸에서 `@`**: 입력하면 공동 메모 제목이 힌트로 뜨고, 고르면 `[@제목](주소)`가 들어간다. 일정 목록/상세에는 그 링크가 클릭 가능한 칩으로 표시되고 누르면 그 메모로 이동한다.
- **앱 전환**: 두 앱의 헤더 제목 자리(`에바스 캘린더 | 에바스 메모`)에서 상대 앱 이름을 누르면 상대 사이트로 이동한다(현재 앱은 강조, 상대 주소가 설정돼 있을 때만 링크).
- **딥링크**: 캘린더 `/?event=<id>` → 그 일정이 있는 달로 이동해 날짜를 선택하고 일정을 강조. 메모 `/?memo=<id>` → 그 메모의 편집 화면. 상대 앱에서 로그인이 필요하면 로그인 뒤 **원래 가려던 딥링크로 돌아온다**(`next`).

## 비목표
양방향 자동 백링크 표시(상대 앱이 "나를 태그한 것" 목록), 태그 변경 알림·푸시, 태그 대상 이름이 바뀌거나 지워졌을 때 본문 링크 텍스트 자동 갱신(칩은 최신 제목/삭제 여부를 조회해 표시만), 개인 메모를 캘린더에서 태그, 일정 제목 칸의 `@`(메모 칸만), 이름이 같은 앱 둘 이상 연결.

## 결정 (제 판단 포함)
- **개인 메모 비노출**: 캘린더 쪽으로는 **공동 메모 제목만** 나간다(일정은 모두에게 보이므로 개인 메모 제목이 일정에 적히면 노출된다). 메모 안에서 메모를 태그할 때는: **공동 메모 본문에서는 공동 메모만**, 개인 메모 본문에서는 공동 메모 + 본인의 개인 메모(링크가 본인에게만 열리므로). 일정은 모두에게 보이므로 어디서든 태그 가능.
- **서버끼리 통신**: 브라우저는 상대 서버를 직접 부르지 않는다(쿠키가 도메인별이라 안 된다). 브라우저 → 자기 서버(로그인 세션 필요, 프록시 경로) → 상대 서버 내부 경로(공유 비밀키). 비밀키는 브라우저에 나가지 않는다.
- **설정(.env, 둘 다)**: `LINK_API_KEY`(두 앱이 같은 긴 값; 비어 있으면 연동 기능 전부 꺼지고 앱 전환 링크만 URL이 있으면 동작), 메모: `CALENDAR_URL`(공개 주소, 없으면 `SHARED_CALENDAR_URL`을 쓴다), `CALENDAR_INTERNAL_URL`(기본 `http://127.0.0.1:<SHARED_CALENDAR_PORT 또는 8000>`); 캘린더: `MEMO_URL`(공개 주소), `MEMO_INTERNAL_URL`(기본 `http://127.0.0.1:8001`).
- **내부 경로 보호**: `X-Link-Key` 헤더를 `secrets.compare_digest`로 확인, 불일치·미설정이면 404. 추가로 Caddy에서 `/internal/*`을 바깥에 404로 막는다(`Caddyfile`, `Caddyfile.shared` 둘 다).
- **태그 저장 형식**: 본문/메모 칸에 `[@제목](공개주소/?event=<id>)` 또는 `[@제목](공개주소/?memo=<id>)` 마크다운 링크 한 개. 제목의 `[` `]` `(` `)`는 `\`로 이스케이프. 칩은 이 형식의 링크 중 주소가 상대 앱/자기 앱 공개 주소로 시작하는 것만 인식한다. 상대 앱 주소가 바뀌면 옛 링크는 일반 링크가 된다(허용).
- **칩 최신화**: 칩은 글의 링크 텍스트를 먼저 보여주고, 자기 서버의 배치 조회(`ids=`)로 최신 제목·날짜와 삭제 여부를 받아 갱신한다(삭제됐으면 취소선·"삭제됨"). 조회 실패는 조용히 무시한다.
- **로그인 `next`**: `/auth/login?next=<경로>`; `next`는 `/`로 시작하고 `//`·`\`·제어문자·`://`를 포함하지 않는 경로+쿼리만 허용(아니면 `/`). 세션에 저장했다가 콜백에서 이동.
- **힌트는 반드시 입력 위쪽에 뜬다(사용자 요구)**: `@` 자동완성 목록은 커서(메모)·입력칸(캘린더) **위쪽**에 표시하고 아래로 뜨지 않는다(위 공간이 목록 높이보다 모자라면 스크롤로 입력 위치를 아래로 밀어 공간을 확보하고, 그래도 안 되면 위쪽에서 목록 자체를 스크롤 가능하게 줄인다). 태그된 일정·메모는 편집 화면 본문 **위**의 연결 칩 줄로도 항상 보이고, 누르면 이동한다.
- **UI**: 칩 줄은 편집 화면 본문 위(태그가 없으면 숨김). 힌트 목록은 입력한 `@` 뒤 글자로 필터(2글자 미만이면 최근 항목), 결과는 일정(날짜 포함)과 메모를 구분 표시, 최대 8개, 디바운스 250ms. 상대 서버가 응답하지 않으면 "연결할 수 없습니다" 한 줄만 보이고 입력은 방해하지 않는다.

## 계약 (두 구현이 반드시 맞출 것)
공통: 제목은 문자열, 날짜는 ISO(캘린더의 `start`/`end` 형식 그대로).

### 캘린더 서버 (evas-calendar)
- `GET /internal/link/events?q=<text>&limit=<1..20, 기본 8>` + `X-Link-Key` → `200 [{id, title, start, end, all_day, category_color}]` (제목 부분 일치(대소문자 무시), q가 비면 오늘 이후 가까운 순. 정렬: 시작일이 가까운 순, 같으면 id 큰 순).
- `GET /internal/link/events?ids=1,2,3` + `X-Link-Key` → 같은 모양 배열(없는 id는 생략).
- `GET /api/link/memos?q=&limit=` (로그인 필요) → 메모 앱의 `/internal/link/memos`를 `X-Link-Key`로 호출해 결과를 그대로 전달. `GET /api/link/memos?ids=` 도 같음. 상대 서버 실패/타임아웃(3초) 시 `502 {"detail": "연결할 수 없습니다"}`. `LINK_API_KEY` 미설정이면 404.
- `GET /api/config` (로그인 불필요) → `{"app": "calendar", "calendar_url": "<PUBLIC_URL>", "memo_url": "<MEMO_URL or null>", "link": <LINK_API_KEY 설정 여부 bool>}`.
- 딥링크 `/?event=<id>`: 화면이 `GET /api/events/<id>`(없으면 새로 추가 필요) 또는 동등한 방법으로 일정을 찾아 그 달로 이동·날짜 선택·일정 강조. 없으면 토스트 "일정을 찾을 수 없습니다".
- `GET /auth/login?next=`.

### 메모 서버 (evas-memo)
- `GET /internal/link/memos?q=<text>&limit=<1..20, 기본 8>&for=<personal 허용 시 사용자 id>` + `X-Link-Key` → `200 [{id, title, updated_at, kind: "shared"}]`. **`for` 없으면 공동 메모만.** 메모 서버 자신의 브라우저 경로가 개인 메모를 포함하는 것과 달리 내부 경로는 항상 공동 메모만 반환한다(`for` 파라미터는 두지 않는다 — 캘린더로 개인 메모가 나갈 길을 만들지 않는다).
- `GET /internal/link/memos?ids=1,2,3` + `X-Link-Key` → 공동 메모만(개인·없는 id는 생략).
- `GET /api/link/events?q=&limit=`, `GET /api/link/events?ids=` (로그인 필요) → 캘린더 내부 경로 프록시(502/404 규칙 동일).
- `GET /api/link/memos?q=&limit=&scope=`(로그인 필요, 메모 앱 자체 조회) → `[{id, title, updated_at, kind}]`: `scope=shared`면 공동만, `scope=all`이면 공동 + **본인** 개인(개인 메모 본문에서 쓸 때). `ids=`도 지원(접근 가능한 것만, 나머지 생략).
- `GET /api/config` (로그인 불필요) → `{"app": "memo", "memo_url": "<PUBLIC_URL>", "calendar_url": "<CALENDAR_URL or null>", "link": bool}`.
- 딥링크 `/?memo=<id>` → 화면이 `#<id>` 경로로 바꿔 편집 화면을 연다.
- `GET /auth/login?next=`.

## 실패로 치는 것
- 개인 메모 제목·존재가 캘린더 서버/일정/내부 경로로 나가는 것.
- `/internal/*`이 키 없이(또는 바깥에서) 응답하는 것. 비밀키가 브라우저 응답·HTML·로그에 보이는 것.
- 상대 앱이 꺼져 있을 때 자기 앱의 편집·저장이 느려지거나 막히는 것(타임아웃 3초, 입력 방해 금지).
- 태그 제목이 HTML로 해석되어 스크립트가 실행되는 것(칩·힌트·일정 메모 칸 모두 textContent).
- 로그인 뒤 딥링크가 사라지는 것, 열린 리디렉션(`next`로 외부 사이트로 보내는 것).
