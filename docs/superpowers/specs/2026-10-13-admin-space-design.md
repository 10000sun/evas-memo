# 전율 탭(관리자 전용 메모 공간) 설계

기존 설계들(`2026-10-13-evas-memo-design.md`, `…folders-markdown…`, `…calendar-memo-link…`)에 더한다. 충돌하면 이 문서가 우선한다. 화면 라벨은 **전율**, 내부 종류(kind) 이름은 `admin`.

## 목표
- 메모 종류가 `personal`(개인) · `shared`(공동) · `admin`(전율) 셋이 된다. 전율은 **관리자 역할(`role = admin`) 전원이 함께 열람·편집**하는 공간이다(공동 메모처럼 실시간 공동 편집, 폴더·분류·마크다운·검색·내보내기 모두 동일).
- 관리자가 아닌 사람에게는 전율 탭이 보이지 않고, 전율 메모·폴더의 **존재가 어디로도 드러나지 않는다**(목록, 검색, 직접 주소·id, 폴더, 실시간 편집 연결, 활동 기록, 푸시, 캘린더 연동, 오류 메시지 차이).
- **옮기기**: 관리자는 개인·공동 메모를 전율로, 전율 메모를 개인·공동으로 **옮길 수 있다**(복사가 아니라 이동; 내용·분류·작성자 유지, 폴더는 NULL로 초기화). 기존 개인→공동 이동, 공동→개인 복사는 그대로.
- **태그(사용자 요구: "전율 내에서는 태그 다 가능")**: 전율 메모 본문에서 `@`는 캘린더 일정 + 공동 메모 + **본인 개인 메모** + **전율 메모 전부**를 힌트로 보여준다. 반대로 캘린더 쪽(일정 메모 칸)과 `/internal/link/*`에는 전율 메모가 나가지 않는다(일정은 모두에게 보이므로 제목이 샌다).

## 비목표
관리자 중 사람별 접근 지정, 전율 활동 기록·푸시·알림, 전율 메모의 캘린더 태그, 전율 전용 분류, 관리자가 아닌 사람에게 "접근 권한 없음" 안내(존재를 숨기므로 404와 같은 응답).

## 실패로 치는 것
- 비관리자가 전율 메모·폴더의 제목·존재·개수를 알 수 있는 모든 경로(REST, 검색, WebSocket, 캘린더 내부 API, 활동·푸시, `rev`, 오류 문구, 폴더 목록).
- 관리자 권한을 잃은 사람(강등·삭제)이 열려 있던 연결로 전율 메모를 계속 읽거나 편집하는 것.
- 옮기는 도중 본문이 사라지거나 두 곳에 동시에 존재하는 것, 옮긴 뒤 이전 종류의 방에 남아 있던 접속자가 계속 편집하는 것.
- 운영 DB(종류가 두 개뿐인 기존 스키마)가 새 버전에서 열리지 않거나 데이터가 사라지는 것.

## 결정 (제 판단 포함)
- **누가 쓰나(사용자 확인 없이 기본값)**: 관리자 역할 전원. 사람별 지정은 하지 않는다.
- **권한 판정**: 요청 때마다 `users` 표의 `role`을 읽는다(기존 `current_user`). `kind == 'admin'` 메모/폴더에 접근하는 모든 경로는 `role == 'admin'`이 아니면 **존재하지 않는 것처럼 404**(목록에서는 제외)로 처리한다. `EVAS_OPEN_EDIT`로 편집자가 된 사람은 관리자가 아니다.
- **스키마 이전**: `memos.kind`와 `folders.kind`의 CHECK가 `('personal','shared')`로 고정돼 있어 SQLite에서는 제약을 바꿀 수 없다 → `db.init`에서 테이블 재작성(새 표 생성 → 복사 → 교체)으로 `('personal','shared','admin')`를 허용하게 한다. 조건: 기존 스키마일 때만(제약 문구 검사), 한 트랜잭션, `PRAGMA foreign_keys=OFF`로 재작성하고 `foreign_key_check`로 확인한 뒤 다시 ON, AUTOINCREMENT 시퀀스(`sqlite_sequence`)·인덱스·`folder_id`/`category_id` 외래키 유지, 멱등, 데이터 보존. `activity`는 `kind IN (add, edit, delete)`라 변경 없음.
- **이동 API**: `POST /api/memos/{id}/move` body `{"to": "personal"|"shared"|"admin"}` (현재 종류에서 허용되는 전이만):
  - `personal → admin`: 소유자이면서 관리자. `shared → admin`: 관리자(작성자 무관, 공동에서 사라지므로 화면에서 확인창). `admin → shared`: 관리자(모두에게 보임; 공동 활동 기록에 '작성', 기존 개인→공동 이동과 같은 방식). `admin → personal`: 관리자, **이동한 사람이 새 소유자**(다른 관리자에게는 사라진다).
  - 그 외 전이(`personal→shared`는 기존 `/share`가 그대로 담당, `shared→personal`은 기존 복사 `/copy-to-personal`)와 권한 없음은 404/403 규칙에 따른다(비관리자는 전율이 관련된 요청이면 존재 숨김 404).
  - 이동하면 `folder_id`는 NULL. `shared → admin`은 공동 활동 기록에 '삭제'로 남기고(푸시는 보내지 않는다), `admin → shared`는 '작성'+푸시, 전율이 관련된 그 밖의 전이는 활동 기록·푸시 없음.
  - **열려 있는 편집 방**: 이동으로 접근 권한이 줄어드는 접속자는 즉시 닫는다(`shared → admin`: 비관리자 접속자 전부, `admin → personal`: 이동한 사람 외 전부, 이때 메모 삭제와 같은 코드 4404). 접속이 허용되는 접속자는 유지한다. 저장되지 않은 편집은 이동 전에 저장한다.
- **관리자 권한을 잃을 때**: `PUT/DELETE /api/users/{id}`로 역할이 `admin`에서 내려가거나 사용자가 삭제되면 그 사람의 전율 메모 편집 연결을 즉시 닫는다(코드 4403). (기존 "연결 후 권한 재확인 안 함" 한계를 전율에 한해 없앤다.) 같은 사람이 다른 종류 방에 연결한 것은 영향 없음.
- **폴더**: `folders.kind`도 `admin`을 허용. 전율 폴더는 관리자 전원이 생성·이름 변경·삭제할 수 있다(개인 폴더는 본인만, 공동 폴더는 기존 규칙 그대로). 메모의 폴더는 메모와 같은 종류여야 한다.
- **목록·검색**: `GET /api/memos?kind=admin`(관리자만, 아니면 404 아님 — **빈 목록이 아니라 404**; 비관리자는 `kind=admin` 자체를 알 수 없게 한다). 다른 종류 조회에 전율 메모가 섞이지 않는다. `GET /api/folders?kind=admin` 동일.
- **활동 기록·`rev`·푸시**: 전율 메모는 어디에도 기록하지 않는다. `/api/activity`의 `rev`와 항목은 공동 메모만 반영.
- **연동**: `/internal/link/memos`는 변함없이 공동만. `/api/link/memos`는 `scope` 값에 `admin`을 더한다: `scope=admin`은 관리자 전용(비관리자는 404)이며 **공동 + 본인 개인 + 전율 전체**를 돌려준다. 전율 메모 화면이 이 scope로 호출하고, 공동 메모는 `shared`, 개인 메모는 `all`(공동 + 본인 개인)을 그대로 쓴다. 응답의 `kind`는 `shared|personal|admin`.
- **화면**: 탭 `개인 | 공동 | 전율`(전율은 관리자에게만 렌더링되고 DOM에도 만들지 않는다), 전율 탭의 새 메모·폴더·분류 필터·검색은 다른 탭과 같다. 편집 화면의 이동 버튼은 현재 종류와 내 역할에 맞는 것만 보인다: 개인(관리자만) "전율로 옮기기", 공동(관리자만) "전율로 옮기기", 전율 "공동으로 옮기기"·"개인으로 옮기기". 확인창 문구: 전율로 → "관리자만 볼 수 있게 됩니다(공동 메모였다면 다른 사람에게는 사라집니다)", 공동으로 → "모든 사람에게 보입니다", 개인으로 → "나만 볼 수 있게 됩니다(다른 관리자에게도 사라집니다)". 전율 탭에서 `@` 힌트는 위 `scope=admin`을 쓴다.
